# 05 — 离线 AEC 与唤醒词打断候选

**What to build:** 用户确认需要保留语音打断，并授权设备不在身边时准备 AEC 候选、主机回归、构建和真机测试方案。正式默认保留已部署的半双工回退。

**Blocked by:** 真实声学和触摸验收需要设备返回；“啊灰啊灰”真实模型由 [04](04-chat-wake-hardware-reset.md) 持有。离线代码和构建不被设备缺席阻塞。

**Status:** ready-for-agent

## Acceptance

- [x] 明确输入布局与播放参考来源，不能把不一致板级注释当作回采证据。
- [x] 默认关闭的候选从真实左 DAC PCM 取参考，保留麦克风并配置 MR／AEC；采样格式、延迟、生命周期和失败有回归。
- [x] 候选关闭播放期间 capture suppression，沿用真实 WakeNet／AgentManager 的唤醒词打断链路，不宣称普通说话已支持打断。
- [x] 聊天增量更新先失败后通过，失败重试、实例重建与私有数据边界有覆盖。
- [x] 完整候选构建、准确输入／镜像证明和统一检查通过，生成明确的回退方式。
- [ ] 真机确认实际麦克风通道、播放参考时序、AEC 初始化及内部 RAM 余量。
- [ ] 无人说话不新增 User STT；近远距离唤醒词打断后可以回答；结束会话／Reset／Home 无回归。
- [ ] 连续语音与滚动不发生触摸超时，原始物理复现通过，记录音频缺口与绘制延迟。

## Comments

当前设备不在用户身边；本轮不操作串口、不播放测试音频、不部署候选。软件参考的时间戳只是 DAC 写入／ADC 读取的估计，零延迟未校准；不能将主机样本对齐测试视为真实 AEC 消除率或双讲成功。实际对齐失败时保留正式半双工版本，并评估板级硬件回采或时钟对齐改进。


### 设备返回后的执行顺序

1. 核对设备 identity，读取最新 App 与 LittleFS 备份并保存 hash；候选安装前保存对应旧 allowlist／私有文件 inventory。只写 App 与保留数据的 LittleFS，不写 NVS、模型、bootloader 或分区表。
2. 先检查 MR／AEC 实际初始化成功、第一通道确为有效麦克风，记录内部 RAM free／largest 和 PSRAM。确认软件参考与扬声器输出相关，测量延迟后重新准备候选；不能将零延迟估计当作校准结果。
3. 每次回复后安静 30 秒，检查实际 User STT／对话历史没有新增；回复 emoji 数不能代替这个断言。近、远距离各 3 次播音中使用唤醒词，要求停止原回复并能回答下一句。目标“啊灰啊灰”模型缺席时只能记录现有词的技术验证，目标验收仍未完成。
4. 主动告别后在当前 Chat 页面唤醒；Chat 前台实体 Reset 后重建 Chat Root 并恢复对话；Home 后 Reset 留在 Watch Face。验证实体操作，不添加界面 Reset 按钮。
5. 连续 3 轮短对话并滚动历史，记录 UDP 缺口、实际 draw／flush 耗时与触摸结果；任何 synthetic input tick timeout 都判失败。音频／性能窗口禁止截图，窗口结束后才捕获并立即 release。
6. AEC 初始化失败、误唤醒、触摸超时或内存不足时停止扩大测试，恢复已核对的 `c60a29d3b` App 和与它匹配的部署前 LittleFS 备份，重新核对 hello、Chat／Home／Reset。回退先保存候选期间新增的用户数据，避免用旧文件系统覆盖新增内容。

离线实现、主机验证及镜像证据见[候选记录](../records/2026-10-08-offline-aec-candidate.md)。
