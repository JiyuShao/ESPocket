# 2026-10-02 — USB 测试准入真机记录

## 范围与镜像

- 设备：已连接的 ESP32-S3 手表；USB Serial/JTAG `/dev/cu.usbmodem101`。
- 最终刷入镜像：`firmware/build/manual-clean-abs/espocket.bin`，SHA-256 `2c414632e7086a3d8c984c7569c2c9dbd06476624462f3fcdbf11d74403c5838`，`hello.image_identity=fcd1a767c`。
- 本记录仅验证 ticket 01 的 USB 准入；合成触摸、PWR、快照和清理由 ticket 02/03 验证。

## 结果

1. 首次刷入后，串口显示 `USB Test Adapter ready; developer mode disabled`；发送 `hello` 得到 `developer_mode_off`。设备正常显示表盘。
2. 在 Quick Settings 点击开发者模式，文字变为 On，设备未重启。串口重新连接触发重启后，日志显示 `developer mode enabled`；`hello` 返回 `version=1`、镜像 identity 与 `capabilities=["hello"]`。
3. 未知版本返回 `bad_request`，未实现的 `stimulus.touch` 返回 `unsupported`。普通日志无 `@ESPTEST ` 前缀，测试响应带该前缀。
4. 最终镜像刷写校验通过，重启日志显示 `ESPocket started` 与 `developer mode enabled`；`hello` 正常返回。设备当前仍开启开发者模式，供后续 ticket 02 的 USB 验证使用。
5. 主机协议测试、Shell 动作文档测试和固件整包构建通过；文档检查通过。

## 失败与修复

- 初版测试任务在内部 RAM 不足时创建失败。将任务栈先从内部 RAM 分配，再安装较小的 USB 缓冲后，适配器正常启动。
- 曾在点击开关时触发 `spi_flash_disable_interrupts_caches_and_other_cpu` 的 PSRAM 栈断言。解码栈从 `CircularShell::on_action` 经 `DeveloperMode::set_enabled` 到 `nvs_open`；NVS 写入从 GUI 回调移至内部 RAM 栈的工作任务。随后真机单次点击成功且重启保持 On。
- 审查发现停止超时可留下运行任务，以及保存超时可能迟到改变准入状态；已修复任务停止等待和请求取消边界。最终镜像验证了启动与 `hello`；这些异常分支只有代码审查证据，尚未注入故障做真机验证。
