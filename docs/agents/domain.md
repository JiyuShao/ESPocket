# Domain docs

Read the following before exploring or changing a domain area:

1. Root `CONTEXT.md` for canonical ESPocket terms.
2. Relevant `docs/adr/` records for decisions that constrain the change.
3. The product contract or architecture view linked by `docs/README.md`.

Use glossary terms in specs, tickets, tests and code-facing proposals. If a proposed change contradicts an accepted ADR, name the ADR and reopen the decision explicitly.

ESPocket uses a single context. `CONTEXT.md` defines terms only; it does not carry implementation status, source paths or design rationale. ADRs explain durable choices, while current work belongs in `.scratch/`.
