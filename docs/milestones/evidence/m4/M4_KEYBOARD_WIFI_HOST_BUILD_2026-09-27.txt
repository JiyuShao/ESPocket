Keyboard privacy boundary
- Core 0.8.4 publishes KeyboardClosed.Text as a service-wide event after invoking the request owner's callback.
- A normally stopped Runtime App cannot observe a later Settings result because Runtime::stop_app releases its subscriptions.
- A hostile Runtime App can deliberately fail its lifecycle on_stop before that cleanup and leave a listener resident.
- ESPocket accepts keyboard requests only from a Running owner app, then latches any Runtime stop failure and rejects subsequent keyboard requests until device/System-object restart. Successful Runtime lifecycle remains enabled.
- This product-level fail-closed containment does not replace the correct upstream owner-scoped event delivery/cleanup fix.
