# ADR-0018: 开发者模式允许未签名 Runtime 包

- Status: `accepted`
- Recorded: 2026-10-04
- Origin: 用户明确选择先仅在开发者模式下允许未签名包。

## Decision

普通模式继续要求有效发行签名；设备上已开启开发者模式时，Core 的同一公开安装边界可以允许完全未签名的 Runtime 包，并持久记录其未验证发布者身份。允许未签名不意味着把损坏、半套或验证失败的发行签名降级处理为未签名。

本决定修订 [ADR-0004](0004-core-owns-the-runtime-package-trust-gate.md) 的无条件发行签名要求，Core 持有单一 gate、不可变 candidate、成员与路径安全、设备兼容性、事务提交、回滚及重启状态验证等决定继续适用。产品契约见 [Runtime 包信任](../design/product/05-runtime-package-trust.md)。

## 开发者兼容运行

用户进一步确认：开发者模式允许所有声明支持 `super` 的 Runtime 包进入 Core 同一安装校验，不要求包白名单；仅放宽目标系统匹配，设备仍声明 `espocket`，原包与 manifest 不变。Runtime、服务、资源及安全检查继续执行，准入不等于已经验证运行兼容性。

这些外部旧包暂不要求 ESPocket 导航契约。内部页面与返回由 App 管理，平台保留启动、停止和 PWR Home；没有真实导航接入时，不生成虚构 Root、Page、canBack 等快照，也不提供指定 Page 打开或统一页面 Back。开发诊断明确导航不可用，用户安装提示不展示导航术语。普通 ESPocket App 的共同导航契约不变。

安装记录分别持久保存未签名例外与 super 系统匹配例外。关闭开发者模式后，依赖任一例外的 App 保留安装内容但禁止启动；运行中的实例必须停止并回 Watch Face。重新开启模式后，重新通过必要准入检查才可启动，不提升发布者信任或声称完整兼容。重启、发现和更新采用一致 policy，不仅限制安装按钮。

安装前显示“开发者兼容安装”，说明目标系统、尚未验证的运行兼容性及关闭模式后的行为。未签名时额外说明发布者身份未经验证。平台兼容能力按具体问题评估与测试；此决定不承诺通用自动导航 Adapter，也不批准所有上游 API 的无条件兼容。
