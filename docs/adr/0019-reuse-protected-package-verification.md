# ADR-0019: 复用受保护安装版本的验证结果

- Status: `accepted`
- Recorded: 2026-10-05
- Origin: 用户明确要求安装完整验证，重启与启动复用持久结果，内容或信任策略改变才重新验证。

## Decision

Core 继续持有唯一 Runtime 包准入与安装事务。完整包、签名、成员摘要和兼容性在安装／更新时验证；结果绑定安装事务、内容摘要、验证规则和信任配置并持久化。重启先处理未完成事务，再复用仍有效的结果；首次迁移、结果缺失／损坏、版本或信任配置变化时完整验证。用户打开 App 时检查有效版本、当前开发者模式与服务要求，不重复扫描包；正常运行不执行包完整性扫描。

此前 [ADR-0004](0004-core-owns-the-runtime-package-trust-gate.md) 的可信重启要求继续有效；“重新验证”不再要求每次开机读取全部内容，而由受保护安装版本与有效持久记录共同证明。不得仅缓存一个通过布尔值。

代码、manifest、资源、原包和验证记录的修改必须经过真实 Storage／Core Owner 的受控入口。普通 App 的 data/cache/files 写入保持有效。修改受保护内容前先持久化验证失效，并清除本次启动的结果；失败或掉电不得继续使用旧记录。更新停止旧实例并提交新目录，保持原事务回滚。关闭开发者模式立即停止依赖例外的实例并禁止再次启动，只检查策略，不重复验证内容。

持久记录使用设备本地认证码，认证材料只由 Core 通过受保护的 Storage KV namespace 保存与访问；Runtime／USB 不能读取、写入或清除此 namespace。记录被伪造、移位或认证失败时，回退完整验证。该本地材料不是发布者身份，也不改变 BPK 签名。外部 Flash 写入或回退到未保护固件不在复用保证内，必须作废记录后重新建立受保护版本。

第一阶段完成验证复用和修改保护。JS 源码、GUI 文档与解码图片的复用按分段测量另行推进；重新打开仍执行既有入口脚本、on_start 与退出清理，不能变成继续运行。

## Consequences

- 文件系统可绕过受控入口修改、保护未启用或记录无法证明归属时，不能复用结果。
- 保留 BPK 格式和原包，不引入第二套安装器或发布者身份。
- 启动延迟与 Flappy 正常运行的 GUI／定时器延迟分别测量。
- 外部正式发布条件和物理断电验收仍独立记录。
