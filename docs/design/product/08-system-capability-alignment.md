# 08 — 系统能力对齐

## 目的

规定系统状态、设备调试、多语言、即时主题、完整文件管理与条件设备功能的共同产品范围。

## 用户结果

用户能辨认真实系统状态，在设备上调试、切换受支持的语言与主题，并完成公共文件的浏览、重命名与删除。系统临时界面、Home 和有效设备能力遵守共同交互规则。

## 产品要求

| ID | Requirement |
|---|---|
| SCA-001 | 系统状态来自真实 Wi-Fi、SNTP、Device Owner；未知、缺失、读取失败和有效结果必须可区分，不把 Service 不可用显示为关闭或零值。状态呈现不创建第二套 Service 状态事实。 |
| SCA-002 | 状态栏展开与 App 内临时状态呈现保留为对齐目标；Watch Face 下拉仍进入 Quick Settings，App 页面普通滚动和 Back 不被系统新增手势静默接管。临时呈现不改变 App Page 栈与唯一 Home。 |
| SCA-003 | 保留设备上的 Settings → Utils → Shell 调试链路，包括 Memory/Thread 浮层、阈值和已有 GUI 调试控制。开发者模式作为产品准入；不支持的采集指标显示不可用，不能以缓存或零值冒充实时数据。设备浮层不能由电脑查询替代。 |
| SCA-004 | 语言切换、字体预载和回退属于产品范围。支持语言由实际字体与翻译资源共同确定；localized manifest name、键盘文本显示和中文输入法是不同能力。App 作者负责其文案，系统负责其维护的 Surface、Overlay 与官方 App 适配。 |
| SCA-005 | Light/Dark 运行中刷新属于产品范围；切换不得重启 App、改变 Page 或 Running Instance，亦不得重新提交键盘/Dialog 结果。启动偏好临时回退继续遵守 OVR-013、OVR-015。 |
| SCA-006 | Files 包含可用卷/目录浏览、容量与信息、重命名、删除及键盘/确认流程。文件预览、播放器和 BPK 安装不由此推导；文件管理不能绕过 Core 包准入、安装/卸载或其他 Owner 的私有数据边界。 |
| SCA-007 | 非 GUI 显示源存在时，系统 UI 可临时取回 GUI；恢复必须属于仍有效的原 Owner 与原 source，不能因同名 source 再注册而复活已结束的实例。PWR Home 始终回 Watch Face。 |
| SCA-008 | Expansion 提示只在真实 ModuleManagerIface 可用时启用，保留初始模块状态与插拔提示。无能力时不产生伪事件，不宣称当前板支持扩展模块。提示复用系统 MessageDialog 与 INT-028–032。 |
| SCA-009 | 手机配网复用 Wi-Fi Owner 的 portal 与连接事实；提交成功、取得 IP、互联网可达和凭据持久化成功必须区分。触发、取消和恢复规则由独立配网设计确认。 |

## AI Native

| ID | Requirement |
|---|---|
| SCA-010 | 状态、文件、主题、语言和配网语义必须从真实 Owner 注册，并按实际调用者的授权、目标和生命周期判定。诊断及内部显示路由不向 Assistant 暴露；原始硬件、全卷路径与 GUI 点击不能代替语义操作。 |

## 非目标

- 用中文显示承诺中文输入法，或用文件操作承诺预览、播放器与包安装。
- 重建网络、存储、采集与显示的事实源。
- 用功能范围代替新权限或改变唯一 Home。
