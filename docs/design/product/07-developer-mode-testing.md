# 07 — 开发者模式与交互验证

## 目的

规定真实设备自动化入口的用户可见开关与证据边界，使开发者能验证同一套产品导航，同时不把合成输入当作物理触控或画面验收。

## 用户结果

- 设备默认不接受自动化命令，用户可在设备上显式开启开发者模式。
- 开发者能重复验证 Home Space、App Page、Back、PWR 和息屏状态。
- 阶段验收能区分合成输入、物理输入和视觉观察。

## 产品要求

| ID | Requirement |
|---|---|
| DEV-001 | 正式固件可以包含交互测试入口，但只有设备上显式开启开发者模式后才接受命令；该设置默认关闭并持久保存。 |
| DEV-002 | 首版交互测试通过 USB 提供；开发者模式开启后可直接使用，不逐次弹出连接确认。Wi-Fi 传输留给后续版本。 |
| DEV-003 | 首版命令只允许合成触摸、语义 PWR、只读状态快照、最终渲染画面截图与输入清理；不得借此安装 App、更改设置或执行任意 App Action。 |
| DEV-004 | 快照必须提供 Home Space Surface、显示状态、前台 App ID，以及由 App 页面栈给出的当前 Page ID、能否 Back 和 Back 待确认状态；状态快照不得暴露页面参数、表单内容或整条栈。截图仅提供当前可见渲染像素，包括系统提示层；不开放私有控件树或隐藏内容，且不能证明实体屏幕亮度与面板输出。 |
| DEV-005 | 测试报告必须分别标记合成输入、物理输入和视觉证据；合成测试通过不得自动计作触摸硬件或画面验收通过。 |

## 开发者安装策略

开发者模式同时作为未签名 Runtime 包安装的用户开关，规则见 [Runtime 包信任](05-runtime-package-trust.md#开发者安装例外)。安装仍通过正式 Core operation；首版 USB 合成输入协议不因此增加安装或任意 Action 命令。

## AI Native

| ID | Requirement |
|---|---|
| DEV-006 | 测试命令不作为 Assistant 可发现或可调用的产品能力；Assistant 的导航语义仍使用对应 Owner 的正式接口。 |

## 非目标

- 首版 Wi-Fi 测试通道、远程认证及云端控制。
- 向自动化开放 App 私有数据、任意脚本执行或产品设置修改。
- 用合成输入替代真机物理触摸、PWR GPIO 和视觉验收。
