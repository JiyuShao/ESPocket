# 05 — Runtime 包信任

## 目的

本契约定义远程 Runtime 包何时可以从外部产物变成用户可启动的 App，确保下载、安装、更新、重启发现和卸载不会绕过同一信任规则。

## 用户结果

- 用户看到“可启动”时，可以确认包已通过对应模式的准入；开发者例外与尚未验证的运行兼容性必须明确区分。
- 安装或更新失败不会破坏原有可用版本。
- 重启不会让未验证、被替换或残缺的包重新出现。
- 验证失败会给出明确结果，不会降级成临时可用状态。

## 产品要求

| ID | Requirement |
|---|---|
| TRU-001 | 来自网络、Catalog、Store、文件导入或其他外部入口的 Runtime 包必须先被视为不可信输入。 |
| TRU-002 | 包的 identity、版本、目标系统、成员集合与内容完整性必须在任何成员可执行前完成统一验证。 |
| TRU-003 | 只有通过对应模式的目标系统与信任判断的包，才能进入已安装集合；开发者准入不得表达为运行兼容性已验证。 |
| TRU-004 | 下载完成不得被表达为安装完成；验证、安装和可启动必须是可区分状态。 |
| TRU-005 | 安装和更新失败时必须保持原版本可用，并清理未提交结果。 |
| TRU-006 | 重启发现必须重新确认已安装状态仍与可信记录一致；无法确认时必须拒绝执行。 |
| TRU-007 | 缺失、额外、重复、路径逃逸、大小写冲突或内容不匹配的成员必须导致验证失败。 |
| TRU-008 | 卸载必须移除 App 的可启动状态和可信 identity；残留文件不得继续产生已安装 App。 |
| TRU-009 | 任一必要信任步骤不可用或结果不确定时，产品必须 fail closed，并提供稳定的失败类别。 |
| TRU-010 | 所有远程安装入口必须得到相同的信任结果，不得存在绕过规则的替代入口。 |

完整验证结果可以在重启与再次打开时复用，但必须绑定安装事务、内容摘要、验证规则和信任配置。代码、manifest、资源及验证记录的修改只能通过受控入口；修改前持久化失效，验证成功后再提交有效记录。普通 data/cache/files 写入不使内容验证失效。无法证明保护有效、记录缺失／损坏或信任配置改变时重新验证，失败不得执行。当前开发者模式和服务要求仍在每次启动时检查。

包可以携带 data/cache/files 初始文件；原始成员与激活前的解包结果必须完整验证。安装后这些目录仍是 App 的可写私有内容，不参与不可变发行内容比较；入口代码和 GUI resource root 不得位于其中。更新保留已有 data/files 用户内容，并补入新的默认文件，安装事务仍须完整提交或回滚。

## 开发者安装例外

普通模式要求发行签名验证通过。设备上明确开启开发者模式时，可以通过 Core 的同一安装边界安装完全未签名的 Runtime 包；安装状态必须明确区分“发布者未验证”和“签名验证通过”，重启或更新不得静默提升信任等级。

未签名例外只放宽发布者签名要求。Artifact digest（若来源提供）、包结构和成员可读性、路径安全、设备兼容性、不可变验证输入、事务提交与失败回滚继续检查。半套签名或发行签名验证失败不能自动降级为未签名安装。

开发者模式还允许声明支持 Brookesia Super 的 Runtime 包进入同一安装校验，不限定包白名单。该例外只放宽目标系统匹配；其他要求仍检查，不承诺运行兼容性。原包内容与设备系统身份保持不变。

外部旧包暂不要求 ESPocket 导航声明；App 管理内部返回，平台提供启动、停止和 PWR Home。没有真实页面语义时，系统不得伪造页面状态或提供指定页面导航。

依赖未签名或 Super 兼容例外的 App，在关闭开发者模式后保留安装内容但禁止启动；正在运行时停止并返回表盘。重新开启后须通过必要准入检查才恢复可用。重启不得绕过此规则，也不得自动提升信任等级。

### 安装提示

标题：**开发者兼容安装**

> 此应用面向 Brookesia Super 系统，尚未验证在 ESPocket 上的兼容性，部分功能或显示可能异常。关闭开发者模式后，应用将停止运行并暂停启动，安装内容会保留。

按钮：**取消 / 继续安装**。

仅当使用 Super 兼容例外时显示上述目标系统说明。仅依赖未签名例外时省略 Super 说明，仍说明关闭模式后的行为；所有未签名包额外显示：**此应用未签名，发布者身份未经验证。** 导航接入详情只进入开发诊断。

## AI Native

| ID | Requirement |
|---|---|
| TRU-011 | 未通过信任判断的包不得向 Assistant 暴露 Context、Action 或 Event。 |
| TRU-012 | 包声明 AI 能力只表示意图，不得自动产生系统授权、用户授权或执行权限。 |
| TRU-013 | 包更新、回滚或卸载后，Assistant 不得继续发现、调用或观察旧版本能力。 |
| TRU-014 | Assistant 必须区分已下载、验证失败、已安装、可启动和已卸载状态，不能用模糊成功信息代替。 |

## 非目标

- 指定包格式、签名算法、事务目录、收据字段或内部安装 Interface。
- 规定 Store 的 UI、Catalog 协议或发布运营流程。
- 用构建时随镜像提供的样例包证明远程分发安全。
